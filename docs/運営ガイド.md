# 運営メンバーのサイト更新ガイド

公開サイト: https://okinawa-atotsugi-moai.github.io/

編集場所: https://github.com/okinawa-atotsugi-moai/okinawa-atotsugi-moai.github.io

## 誰が編集できる？

- サイトとソースコードは誰でも閲覧できます。一般の人は公開内容を直接変更できません。
- 編集できるのは所有者と、所有者がGitHubの「Settings → Collaborators → Add people」で招待したメンバーです。各自のGitHubアカウントを使い、運営用アカウントのパスワードは共有しません。
- メンバーは作業用ブランチで修正し、Pull Request（修正案）を出します。公開用のmainは、所有者 `okinawa-atotsugi-moai` の承認を必要とする設定です。承認後はメンバーも統合できます。
- 所有者自身の修正案は自己承認できないため、所有者は内容を確認して管理者の例外で統合できます。AIに依頼する場合も、公開の指示があるときだけ統合してください。
- 外部の人もコピーや修正案の提出はできますが、承認なしに本番へ反映できません。
- メンバーを追加するには、その人のGitHubユーザー名が必要です。

## AIなしでイベントを更新

1. GitHubで `site/content/event.json` を開き、鉛筆ボタンを押します。
2. 次の項目を変更します。引用符やカンマは消さないでください。

| 項目 | 記入する内容 |
| --- | --- |
| title | イベント名。空欄なら準備中表示 |
| status | 募集中・準備中など |
| date | 日時（案内用の文字列） |
| venue | 会場 |
| fee | 参加費 |
| url | 申込先URL |

3. 「Commit changes」で新しいブランチを作成する選択肢を選び、Pull Requestを作ります。
4. 所有者が内容を確認し、mainへ統合します。
5. Actionsの「Publish Moai website」が緑になったら公開サイトを確認します。

このファイルは次回イベント用です。過去の開催記録や写真、文章・配置の変更は新しいチャットに依頼できます。

## noteはいつもどおり投稿

公式noteのRSSを約6時間ごとに取得し、最新3記事へのリンクを表示します。AIやパソコンの起動は不要です。手動反映はActions → Publish Moai website → Run workflow（main）。定期処理は遅れる場合があり、長期間リポジトリに活動がない場合は再有効化が必要です。

## 新しいチャットで編集を再開

同じパソコンなら、このプロジェクトのフォルダーを開いた新しいチャットで、以下を送ってください。

```text
沖縄アトツギモアイのサイト編集を引き継いでください。
リポジトリ: https://github.com/okinawa-atotsugi-moai/okinawa-atotsugi-moai.github.io
AGENTS.md、README.md、docs/引き継ぎ.md、docs/運営ガイド.mdを読んで、現在の変更状況を確認してください。
今回の修正: 【ここに依頼を書く】
作業ブランチとPull Requestを作成し、公開前にプレビューを見せてください。
```

公開まで任せる場合は、末尾に「確認後、公開までお願いします」と追記します。

## 別のパソコンで編集

1. Gitを用意し、GitHubの招待を自分のアカウントで承認します。
2. 次のコマンドで取得します（GitHub DesktopのCloneでも可）。

```sh
git clone https://github.com/okinawa-atotsugi-moai/okinawa-atotsugi-moai.github.io.git
cd okinawa-atotsugi-moai.github.io
```

3. そのフォルダーを使っている編集ツールで開き、上の依頼文を送ります。AI契約は任意で、GitHub上のイベント編集には不要です。
4. ローカル確認にはPython 3を使います。追加ライブラリは不要です。

```sh
python -m http.server 4173 --directory site/dist --bind 127.0.0.1
```

http://127.0.0.1:4173/ を開きます。更新開始時は未保存・未コミット変更を確認し、勝手に消さないでください。

## 戻したいとき

変更したPull Requestの「Revert」で取り消し用の修正案を作成し、内容を確認して統合します。過去の修正を消す強制上書きは使いません。
